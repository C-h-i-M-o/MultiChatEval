# v2 版本开发计划

最后更新：2026-06-27

> 归档说明：本文档是 v2 历史开发计划。v2 已冻结，未完成内容不再作为当前开发目标。当前开发方向见 `../react-rewrite/`。

## 0. 冻结说明

v2 版本开发已经结束并冻结。本文档作为历史开发计划保留，用于说明 v2 原始目标、阶段拆分和曾经规划的能力边界；未完成的语义分析、模型推荐、运行监控、自动路由等内容不再作为当前开发目标继续推进。

当前项目新的开发方向是前端技术栈重构：保留原 `vue-frontend/` Vue 前端作为可运行基线，将 `frontend/` 作为 React 技术栈主前端，并复用现有 FastAPI 接口、数据库结构、评分逻辑和权限模型。

## 1. 版本目标

v2 版本原计划将 MultiChatEval 从本地 demo 系统升级为可部署到云服务器的在线多用户系统。核心变化是：模型 API Key 与模型参数由管理员统一配置，普通用户只负责使用系统；系统按用户统计 token 消耗并执行每日额度限制；反馈统计、模型推荐、服务健康监控、调用失败分析和成本趋势统计形成可用闭环。

截至冻结时，v2 已保留可运行的多用户评测、管理员模型配置、Token 额度、历史任务、反馈评论和反馈统计闭环。未落地的后续能力不再继续开发。

## 2. 核心假设

- 系统部署在云服务器，普通用户不需要本地部署，也不需要配置模型 API Key。
- 账号体系先分为普通用户和管理员两类角色。
- 管理员负责维护模型供应商、模型配置、API Key、模型参数和用户 token 配额。
- 普通用户可以发起评测、查看自己的历史任务、提交反馈和评论，但不能访问模型配置、系统统计和管理接口。
- 以下假设属于历史规划，不再作为当前实现目标：v2 使用 `Qwen/Qwen3-Embedding-0.6B` 作为统一语义分析模型；模型推荐先做可解释推荐，不在 v2 默认启用自动路由。

## 3. 总体架构

```text
Vue 前端（现有基线，React 重构期间保留）
  ↓
FastAPI API
  ├── Auth / RBAC
  ├── Evaluation Service
  ├── Token Quota Service
  ├── Semantic Analysis Service
  ├── Feedback Analytics Service
  ├── Model Recommendation Service
  └── Operations Metrics Service
  ↓
MySQL

Qwen3-Embedding-0.6B 服务（历史规划，已冻结）
  ↑
Semantic Analysis Service
```

语义分析模块是 v2 的历史规划能力，冻结后不再继续开发：

- 任务分类与模型推荐：基于用户问题向量、任务类型原型库和历史相似问题，判断问题更接近哪类任务，以及哪些模型在相似任务上表现更好。
- 规则评分相关性升级：基于问题向量、回答向量、历史相似样本和现有规则信号，提高相关性评分可信度。

## 4. 开发顺序

### 阶段 1：账号体系与权限控制

目标：完成普通用户与管理员用户的登录、鉴权和权限隔离。

开发内容：

- 增加开放用户注册能力，注册用户默认为普通用户。
- 增加登录、退出、当前用户信息接口。
- 使用 Argon2 密码哈希和 HttpOnly Cookie JWT，访问令牌默认 8 小时过期。
- 增加角色字段，至少支持 `user` 和 `admin`。
- 首个管理员通过命令行脚本创建，不提供默认管理员密码。
- 后端为模型配置等管理接口增加管理员权限校验；用户额度接口留到阶段 3。
- 前端根据用户角色控制导航入口和页面访问。
- 匿名用户反馈逻辑迁移为真实用户归属。
- 评测任务支持 `public` 和 `private`；公开任务对所有登录用户可见，私有任务仅创建者可见。

验收标准：

- 普通用户无法访问模型配置接口和管理页面。
- 管理员可以维护模型配置。
- 历史任务、反馈和评论能正确归属到登录用户。
- 公开任务可由其他登录用户参与评测，私有任务只对创建者可见。
- 未登录访问需要认证的接口时返回明确错误。

### 阶段 2：管理员模型配置改造

目标：将 v1 面向本地部署的“用户自行填写 API Key”改为 v2 的“管理员统一配置模型”。

开发内容：

- 模型配置接口改为管理员专用。
- 普通用户评测页只展示管理员启用且可用的模型。
- 模型配置增加模型参数管理能力，例如默认温度、最大输出 token、超时时间、单价和备注。
- API Key 存储继续隐藏原文，后续可升级为加密存储。
- 模型连接测试仅管理员可用。
- 提供六家常见官方供应商预设和 OpenAI-compatible 空白模板；预设只填充兼容地址和帮助链接，不自动创建数据库记录。
- 单价统一按每 100 万 Token 配置，分为输入、输出、缓存命中、缓存创建四项，并为每个模型选择 CNY 或 USD。

验收标准：

- 普通用户不能新增、编辑、删除或测试模型配置。
- 管理员修改模型启用状态后，普通用户可选模型列表同步变化。
- 评测任务记录实际使用的模型配置和关键参数快照。
- 模型配置页向非专业用户解释参数意义、填写方式和官方资料入口。

### 阶段 3：Token 统计与每日额度

目标：按用户统计 token 消耗，并限制普通用户每日 token 总量。

开发内容：

- 在模型回答记录中明确保存输入 token、输出 token、总 token 和估算成本。
- 增加用户每日额度配置。
- 增加 token 使用流水，记录每次评测任务、每个模型、每个用户的消耗。
- 增加每日用户用量汇总。
- 发起评测前检查剩余额度。
- 模型返回后按实际 token 消耗扣减或补充记录。
- 前端展示当前用户今日已用 token、剩余额度和超额提示。
- 普通用户默认每日额度为 100,000 总 Token，管理员不限额。

验收标准：

- 用户超过每日额度后不能继续发起评测。
- 管理员可以调整单个用户每日 token 上限。
- 失败调用不应错误扣减输出 token，但可记录失败请求和已产生的输入 token。
- 每日额度按北京时间自然日统计。
- 发起任务前只检查是否仍有余额，模型完成后按实际总 Token 累计；当前任务允许轻微超额。

### 阶段 4：语义分析模块与相关性评分升级

目标：使用 `Qwen/Qwen3-Embedding-0.6B` 建立统一语义分析模块，复用到任务分类、模型推荐和相关性评分。

技术选型：

- 默认模型：`Qwen/Qwen3-Embedding-0.6B`。
- 主要用途：文本检索、分类、聚类、相似度计算、代码相关任务语义表示。
- 运行方式：部署为独立 embedding 服务，由后端通过内部 HTTP 或本地服务调用。
- 不使用便宜大模型兜底，避免评分链路漂移和额外调用成本。

开发内容：

- 新增 `SemanticAnalysisService`。
- 为用户问题生成 embedding 并缓存。
- 为模型回答生成 embedding 并缓存。
- 建立任务类型原型库，例如通用问答、代码、写作、总结、翻译、推理、格式化输出、信息抽取、高风险建议等。
- 使用问题向量与任务原型向量计算任务类型候选和置信度。
- 使用问题向量召回历史相似问题。
- 使用问题向量与回答向量计算语义相关性。
- 将 embedding 相关性与现有规则相关性合成：

```text
Relevance = 语义相似度信号 + 显式要求覆盖 + 回答聚焦度 + 离题惩罚 + 拒答合理性
```

- 新增相关性置信度：

```text
高置信：embedding 信号、规则信号和显式要求覆盖一致
中置信：语义相关但显式要求覆盖不完整，或回答较泛
低置信：问题短且多义、回答过泛、embedding 与规则信号冲突
```

验收标准：

- 相同问题和回答在相同模型版本下得到稳定的 embedding 相关性结果。
- 相关性评分详情能展示语义相似度、规则信号和置信度。
- 任务分类结果可被模型推荐复用。
- embedding 服务不可用时，系统返回明确错误或按配置降级到 v1 规则相关性，不静默给出误导性高置信结果。

### 阶段 5：反馈统计页

目标：将 v1 已持久化的点赞、点踩、评分和评论数据转化为可读统计看板。

开发内容：

- 增加模型维度统计：平均最终分、规则分、Judge 分、点赞数、点踩数、点赞率、评论数、调用次数。
- 增加时间维度统计：最近 7 天、30 天和全部历史；评分与调用按回答创建时间统计，互动按反馈或评论提交时间统计。
- 普通用户查看本人创建任务的模型表现、收到的反馈以及本人提交的互动汇总，不暴露其他用户身份明细。
- 管理员查看全局汇总、模型表现、每日趋势和反馈/评论明细，明细支持按模型、互动类型和时间范围筛选。
- 前端恢复反馈统计导航入口，并根据当前登录角色加载个人或管理员统计接口。
- 任务类型统计延后到任务分类结果完成持久化后实现；首版不增加自定义日期、导出、缓存或模型推荐。

验收标准：

- 管理员可以查看模型质量趋势和反馈分布。
- 普通用户可以查看个人统计，但不能访问全局统计接口或其他用户互动明细。
- 最近 7 天、30 天和全部历史均按北京时间自然日返回稳定结果。
- 统计结果和数据库明细可对齐。

### 阶段 6：模型推荐页

目标：基于语义分析、历史评分、反馈、成本和稳定性，为用户提供可解释模型推荐。

推荐输入：

- 当前用户问题的任务类型和分类置信度。
- 当前问题的历史相似问题。
- 相似任务下各模型的最终分、点赞率、失败率、平均延迟和平均成本。
- 当前用户剩余 token 额度。
- 管理员启用的模型集合。

推荐模式：

- 综合推荐：平衡质量、反馈、成本和速度。
- 高质量优先：更重视最终分、Judge 分和点赞率。
- 低成本优先：更重视单位 token 成本和用户剩余额度。
- 快速响应优先：更重视延迟和失败率。

推荐分示例：

```text
RecommendationScore =
  质量权重 × 历史最终分
+ 反馈权重 × 点赞率
+ 稳定性权重 × 成功率
+ 成本权重 × 成本优势
+ 速度权重 × 延迟优势
+ 相似度权重 × 历史相似样本可信度
```

开发内容：

- 新增模型推荐接口。
- 新增模型推荐页，展示推荐模型、推荐理由、关键指标和置信度。
- 在评测页提供“使用推荐模型”入口。
- 推荐理由必须来自结构化指标，不由大模型自由生成。
- 当相似历史样本不足时，展示冷启动推荐，并明确说明依据不足。

验收标准：

- 用户可以在提问后获取 1 到 3 个推荐模型。
- 推荐结果展示可解释理由，而不是只给排序。
- 推荐不会选择已禁用、无 API Key 或超出用户额度约束的模型。
- 低置信推荐必须显式提示。

### 阶段 7：服务健康监控、失败分析与成本趋势

目标：让管理员看到系统是否健康、模型调用为何失败、成本是否异常增长。

开发内容：

- 增加模型供应商维度健康状态。
- 记录每次调用的状态码、错误类型、错误信息摘要、耗时、重试次数和 token 消耗。
- 增加失败分析页：按供应商、模型、错误类型和时间聚合。
- 增加成本趋势页：按天、模型、用户、任务类型展示 token 与成本。
- 增加基础告警规则，例如失败率超过阈值、成本突增、某模型连续不可用。
- 预留 Prometheus 或外部可观测平台接入点。

验收标准：

- 管理员可以定位最近失败最多的模型和错误类型。
- 管理员可以查看每日 token 与成本趋势。
- 健康检查不只返回 API 是否存活，还能反映数据库、模型供应商和 embedding 服务的状态。

### 阶段 8：后续路由器集成预留

目标：为 v3 或更晚版本接入 RouteLLM、LLMRouter 或 LiteLLM 留出架构位置，但 v2 不默认启用自动路由。

预留设计：

- 在模型配置中预留 `model_type`，区分普通模型和路由器模型。
- 路由器模型仍以 OpenAI-compatible endpoint 形式接入。
- 调用记录需要保存路由器返回的实际命中模型。
- 推荐页可以先推荐路由器配置，但必须展示它是“自动路由配置”。

预期接入方式：

```text
用户问题
  ↓
语义分析与额度检查
  ↓
选择普通模型或路由器模型配置
  ↓
调用 RouteLLM / LLMRouter / LiteLLM endpoint
  ↓
记录实际命中模型、token、成本、延迟和失败原因
```

## 5. 数据结构规划

v2 预计新增或调整以下数据结构，实际字段以实现前的数据库设计文档为准：

- `users`：增加角色、状态、最后登录时间等字段。
- `user_token_quotas`：保存用户每日 token 上限。
- `token_usage_logs`：保存每次模型调用的 token 使用流水。
- `daily_user_token_usage`：保存用户每日 token 汇总。
- `semantic_embeddings`：保存问题和回答的 embedding 缓存元数据。
- `task_semantic_profiles`：保存任务类型、置信度和相似问题信息。
- `model_recommendation_snapshots`：保存推荐结果、推荐理由和推荐时的指标快照。
- `model_call_logs`：保存调用状态、错误类型、供应商响应和成本信息。

## 7. 开发流程

本节为历史开发流程。v2 冻结后不再按下列阶段继续推进；后续 React 重构需要另行编写 React 前端设计文档和实施计划。

每个阶段原计划按以下流程推进：

1. 更新对应设计文档：涉及接口先更新 `docs/api.md`，涉及数据表先更新 `docs/database.md`，涉及架构先更新 `docs/architecture.md`，涉及功能状态先更新 `docs/system-features-status.md`。
2. 补测试用例：后端优先补接口、服务和数据库持久化测试；前端补关键交互和权限可见性验证。
3. 实现最小闭环：每个阶段先保证一个可运行路径，再补统计和展示细节。
4. 本地验证：后端运行 `pytest -q`，前端运行 `pnpm build`，最后运行 `git diff --check`。
5. 文档复核：确认 `README.md`、`AGENTS.md` 和 `docs/` 中的描述没有与实现冲突。

## 8. 发布验收标准

v2 原发布验收标准如下。冻结后，未完成条目不再作为必须补齐的发布目标：

- 普通用户和管理员权限隔离正确。
- 普通用户不能配置模型 API Key 或模型参数。
- 管理员可以配置模型 API Key、模型参数和用户 token 额度。
- 普通用户每日 token 限制可生效。
- 评测任务能记录用户、模型、token、成本、评分、反馈和评论。
- `Qwen/Qwen3-Embedding-0.6B` 语义分析结果能用于任务分类、相关性评分和模型推荐。
- 反馈统计页可以展示真实统计数据。
- 模型推荐页可以给出可解释推荐和置信度。
- 管理员可以查看服务健康、调用失败和成本趋势。
- 所有新增接口、数据结构和功能状态均有对应文档。
